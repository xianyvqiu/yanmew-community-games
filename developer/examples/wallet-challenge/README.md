# 喵币计算挑战：钱包与存档恢复示例

这是可打包安装的SDK开发示例，不是社区目录中的正式游戏。使用宿主协议1.0.0，不需要联网或聊天模型。每次开始扣1喵币，答对加法题奖励2喵币；没有每日次数限制，仅在独立、可丢弃的颜喵资料中测试，避免改变个人钱包。

## 运行

1. 使用开发工具包1.0.2及以上的CLI打包本目录，再执行validate。命令见工具包根README；源目录改为本示例所在目录。
2. 从颜喵“小游戏插件 → 从本地安装”安装`.yanmew-game`，核对名称和`wallet.modify`权限，允许后打开。
3. 开始一局、答错一次再答对；核对余额和账单只有一次-1、一次+2。关闭重开可继续未答完的题目。
4. 拒绝权限时示例停止开始，解释所需授权；重新允许后须关闭重开。浏览器模拟宿主不支持真实钱包，不能用其结果代替颜喵实测。

## 结算顺序

代码入口为`ui/main.js`。先保存`state.main.pending`中的完整请求及目标进度，再调用钱包；成功后才保存目标进度并清除pending。界面锁住重复点击，不在每局结束调用`game.complete()`，同一窗口可连续玩多局。

- 请求ID由操作类型和局ID组成；一局的入场与奖励分别只有一个稳定ID。
- 响应丢失、存档写入失败或关闭重开后，使用pending里的原`request_id/game_run_id/delta/reason`核对。
- 宿主返回duplicate时只落实一次目标进度；不重新增加胜场。
- 未确认或被拒绝的旧运行请求保留pending并停止新的结算，提示联系作者、核对账单；示例不擅自清空pending、退款或换ID重发。
- 读取到不兼容存档时保留原数据并停用开始操作。存档版本为1，修改结构时须增加版本并提供迁移。

这是教学流程，不提供完整商业游戏的规则、防作弊、结算人工处理或UI。可复制后换成自己的稳定ID、名称与玩法，按真实业务完善错误处理；不要把示例ID和名称作为自己的作品投稿。

## 验收边界与许可

源码配有模拟钱包的故障测试，验证重复点击、未知响应、保存失败与重开核对；结构打包与真实钱包游玩是不同验收项。真实安装、授权、扣费/奖励及不同窗口尺寸仍需作者在颜喵中手动确认。
